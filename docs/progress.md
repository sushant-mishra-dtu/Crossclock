## Current position

The measurement sprint started on 14 October 2026. **C01 is complete as a diagnostic baseline** under the registered 180-second NVIDIA timeout: three matched cold/warm pairs on one configuration, with every warm run's cache seed verified by hash. On 16 October the owner approved a new 144-send NVIDIA allowance. A seeded warm run finished recovery pair 2 and pair 3 ran cold and warm, using 83 sends and 24 Jev sends with no failure. Median research time to a persisted report was 371.908 s cold and 435.775 s warm (n=3 each). The 10 ms synthetic source cache cannot explain that difference, so there is no cache-speed claim. The original 60-second cohort keeps one complete pair and is not pooled. [The benchmark record](benchmarks/c01.md) has the details. No live calls remain running.

**C03 now passes its full offline acceptance gate** (19 October; PR #3 is now merged). Both failures left from 17 October were outdated fixtures: the sentiment output now includes `run_checks`, and the memory regression must supply completed required stages and use the real completion gate. Production completion checks remain intact. The Windows Python 3.13 gate passed 2,120 tests, with four skips (three POSIX-only checks and optional Bedrock), one integration test deselected, and Ruff clean. Its [design](adr/0001-bounded-execution-and-run-status.md) was approved as proposed: a 1,200 s Standard deadline, a 180 s attempt timeout for every provider, partial reports saved by default, and claim-check failures labelled only. Source inspection found the app had no request timeout at all for NVIDIA and Anthropic models; every provider now gets one. One retry loop with deadline-aware waits replaces the two stacked layers. Stop and the deadline refuse every later HTTP send, SDK and Jev retries included. A stopped, timed-out or failed run saves a partial report with no rating, and records no decision. Offline tests cover these paths; no live provider call or browser walkthrough was made.

**C04 is built and fixture tested** (19 October; review pending; [design record](adr/0002-shared-evidence-and-bounded-retrieval.md)). Each research run gets its own evidence session: identical requests in the run fetch once, concurrent callers share one in-flight request, failures and unavailable answers are never reused, price and news are reused for 60 s and financials for 300 s, and each source has at most two acquisitions in flight. Inside a run the news text and the news items share one acquisition. Alpha Vantage feed items are now trimmed to the requested window, and feed items keep their URL and full UTC publication time. On synthetic sources, a seven-read router workload fell from 42 to 18 acquisitions and C01's real-graph fixture from 13 to 12, with every routed answer unchanged. There is no latency, cost or live duplicate-rate claim: the fixtures have no delays and no live run was made. The code reached `main` as `07220d2`, committed and pushed from the shared checkout before the end-to-end wiring test and these documents were finished; a follow-up PR adds them.

**C05 is built, fixture tested and walked through** (20 October; integrated through [consolidation PR #8](https://github.com/sushant-mishra-dtu/Crossclock/pull/8); [ADR 0003](adr/0003-research-brief-and-source-drawer.md), accepted as proposed on 19 October). A saved report now opens on a brief: run state in words, rating (none for partial research), the Portfolio Manager's summary with currency "not recorded", each checked statement with its verdict, the sources behind its section and a figure trace to the source line that states it, headlines read, data coverage and missing inputs with fixes. A keyboard- and mobile-ready drawer shows each source's readers, arguments, vendors, window, fetch time, coverage, hash, links and verified text. 40 new tests, 14 of 14 planted bugs caught, full offline gate 2,265 passed; the walkthrough passed 31 of 31 checks at 1440 px (both themes) and 375 px and found three faults, fixed ([record](benchmarks/c05-walkthrough.json)). Fixture tested only: no live run and no user has used it. Source review for the design found that what each analyst read is discarded with its private message history, the claim check is saved only as Markdown, and the Reports page shows neither the run status nor any source. The proposal records every tool result and prefetched feed as an evidence entry (gaps included), stores the texts content-addressed, saves the claim check as data, links thesis claims to sources in code (the section's sources plus a figure trace, no new model call), assembles a brief from saved fields, and adds a keyboard- and mobile-ready source drawer.
