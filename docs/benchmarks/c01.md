## Trace contract

[RunTrace](../../tradingagents/telemetry.py) assigns run and parent/child span
IDs, UTC timestamps and monotonic millisecond durations. The web analysis job
starts its trace on submission, before queueing. It saves success, error and
cancelled traces under `results_dir/telemetry/`; trace-write failure does not
discard a completed report. The analysis detail API exposes compact metadata.
Library callers can opt in with `use_trace(trace)` and a `StatsCallbackHandler`.

Spans cover graph nodes, model generations, tool calls, routed sources,
OpenAI-compatible outer invocations/retry waits, HTTPX/HTTPX2 sends, Jev,
setup, queueing and report/state/memory persistence. OHLCV/SEC cache events
distinguish hits and misses. Default-client hooks preserve provider transports,
timeouts and retries. SDK retry counters are recorded when exposed. Requests
dispatches that a benchmark guard refuses are `not_sent`.

An outer retry can make several generation attempts in one public model
invocation. Trace metrics separate these from observed HTTP sends. Existing UI
`llm_calls` remains a generation callback count. Reported input tokens include
cached input; cached input is a separate subset, never added a second time.
Absent usage/cache fields and unpriced costs remain unknown.

Routine traces use allowlisted metadata. They exclude prompts, documents,
tool arguments, response bodies, credentials and exception messages. Endpoint
metadata keeps only an origin and a fingerprint. Raw benchmark responses and
report exports live in the explicitly ignored `/results/` directory; credentials
remain in ignored `.env` files.

Milestones distinguish backend generated-report availability and persisted
reports. Browser rendering and the usefulness/source support of a rendered
result are unobserved. There is no Quick brief path to time yet. A persisted
current report is not relabelled as a fully source-validated brief. Unsupported
Google/Bedrock transports, unobserved SDK wait times, direct source transports
and missing token fields have explicit gaps.

Warm source cache is copied from the preceding cold run. Each graph/model/memory
instance starts fresh. Model tool choices may differ, so a warm run can still
miss a cache entry; source request/hit counts make that visible. Client reuse
in the component probes is a connection experiment, separate from data-cache
warmth. Reports are regenerated in every graph run.

The owner authorized a total Jev ceiling of US$1. The component probe reserves
at most $0.016515072; the graph has a separate $0.98 ceiling. Every actual Jev
send reserves the full documented 65,536-token request maximum at $0.042 per
million input tokens before transmission, including failed attempts; reservations
are not refunded. Combined worst-case reservation is below $1. The published
input rate and free output were checked on 14 October 2026 in the
[official model reference](https://docs.typesafe.ai/models). This is an inference
cost estimate, not an account billing statement.

NVIDIA's [model page](https://build.nvidia.com/nvidia/nemotron-3-super-120b-a12b)
offers a free prototype endpoint, while its
[FAQ](https://docs.api.nvidia.com/nim/docs/faq) says remote API calls consume
trial credits. This account's remaining quota is unknown. Dollar cost is
therefore unknown; request counts are retained and guards stop on quota/auth/429
failure. No credits were purchased and no account limit was changed.

## Results recorded so far

Offline: 24 samples, no failures. All six graph runs generated the same semantic
report/rating fingerprint, with 15 scripted model calls and 13 source requests
each. Cold runs fetched 12 times; warm runs fetched zero times and had 13 hits.
Fixture-only duplicate coalescing reduced three fetches to one while preserving
all three answers. This is not a production coalescing implementation or a
measured live speedup. Three cancellation samples retained the completed source
and made no subsequent model call. Missing data and retries stayed visible.

The cold fixture median was 2.011 s and the warm median 1.393 s. The first cold
sample took 73.769 s, including lazy Python/dependency initialization on the
Windows-mounted checkout. It is retained, not excluded. This setup effect and
concurrent verification make the tiny fixture distribution unsuitable for a
provider-performance claim. First backend report medians were 0.216 s and
0.131 s; rendered first-useful-result remains unknown. The sample maximum is
only an exploratory nearest-rank p95 at n=3.

Jev component: six successful sends, 1,860 input and 144 output tokens;
estimated inference cost $0.00007812. Fresh-client latencies were 1.977, 0.569
and 0.746 s; reused-client latencies 1.299, 0.449 and 0.381 s. This measures a
small typed-question request, not a research report.

NVIDIA component: six successful sends, 444 input and 66 output tokens; every
response finished normally. Fresh-client latencies were 7.886, 1.304 and 2.050 s;
reused-client latencies 1.606, 0.392 and 0.639 s. There is no qualified tail or
causal connection-reuse speed claim at this sample size.

Live graph: three reports completed, one run failed at the local send guard,
and two registered runs were not started. The graph used 96 NVIDIA sends and
26 Jev sends. Including component probes, this attempt used 102 NVIDIA sends
and 32 Jev sends. Total reported Jev inference cost is estimated at
**$0.00142107**; the conservative reservation for sends actually attempted was
**$0.088080384**, below the owner's $1 ceiling. Stop reason was the local
`send_budget_exhausted` guard; the account's remaining NVIDIA quota is still
unknown.

## Contributors and selected experiment

The first cold live run spent about **97.848 s before its setup span**, including
lazy application/dependency imports. Subsequent pre-setup intervals were below
one second. This interval is part of submission-to-completion wall time but was
not attributed to a named import span in this first runner. Web jobs already
place their imports inside setup. Future comparison runs must separate process
warm-up from source-cache regime and span the runner's imports explicitly.

After initialization, the top three named cold-run contributors were:

| Node | Median inclusive wait | Completed samples |
| --- | --- | --- |
| Bear Researcher | 36.522 s | 2 |
| Market Analyst | 34.070 s | 2 |
| Bull Researcher | 29.920 s | 2 |

The warm sample instead put Fundamentals Analyst (42.183 s), Market Analyst
(40.115 s) and Bear Researcher (37.940 s) first. Analysts overlap, so add only
their maximum dependency path when interpreting the barrier. Nested LLM/tool
spans are already inside node durations. With n=1/2, changing model tool choices,
synthetic source delays and concurrent local verification, these rankings are
diagnostic hypotheses rather than stable provider/product distributions.

**Selected first optimization experiment:** request shorter, source-grounded
bull/bear arguments while keeping all nodes, model settings and source coverage
in the comparison. In the first live run those stages generated 2,041 and 2,048
tokens and waited 36.621 and 32.286 seconds. Compare explicit concise prompts
against this retained baseline on a frozen claim set; require preserved material
claims, disagreements and source support. Lowering the token ceiling alone can
truncate answers, so it is not a quality-preserving optimization claim. No
candidate prompt or production pipeline optimization was made in C01.

## Attribution correction and remaining acceptance

Review found that callback ancestry attached generation spans directly to the
graph node instead of the surrounding public invocation. The original logical
call metric therefore counted each successful invocation twice. Production
callbacks now prefer the active invocation parent, with a real SDK retry plus
graph-ancestry regression. `finish_reason` is also recorded when provided, so
future capped responses can be identified rather than guessed from token count.

[The offline derivation helper](../../scripts/repair_c01_trace_parents.py)
corrected 101 uniquely matched parent links in the six saved traces. The helper
requires the same model, sibling parent and enclosing time interval; ambiguous
matches are retained unchanged. There were zero ambiguous/unmatched links.
Each exact original remains in `trace.original.json`, with its hash recorded in
the corrected trace. Timing, usage, HTTP sends, statuses and source events are
unchanged. The repair made no API calls. The local correction manifest is
`attribution-corrections.json`; the original aggregate is `summary.original.json`.

**C01 remains In progress.** Instrumentation and the initial diagnostic are
implemented and verified. Finish at least three comparable paired repetitions
under an explicitly registered available NVIDIA allowance, separate process
initialization, and retain render/check coverage gaps before passing G1. A larger
NSE/US corpus, real-source timing, rendered first-useful-result measurement and
quality reference set remain unqualified. These samples do not pass the product
speed/quality gates.
